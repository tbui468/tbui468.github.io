Postgres SQL Queries with AdventureWorks Part 1

Motivation

This is a series of writeups to help me learn more about Postgres (and SQL by extension). I've recently become interested in database internals and want to test my understanding of a RDBM system before trying to get too deep into building one. The first few posts in this series will focus mainly on querying a database. I've asked an LLM to generate a series of increasingly complex tasks to use as a roadmap. The few sets are quite basic, but it serves as a good warmup since I haven't looked at SQL for a while. After each solution is a note on something I found interesting.

The Database

AdventureWorks is a free database created by Microsoft that models a fictional bicycle selling business. This github repo has information/scripts to load it into Postgres: https://github.com/lorint/AdventureWorks-for-Postgres.

Single Table Queries

  1. Employees hired after a date
    Find employees hired after January 1, 2010.
    Return:
    - BusinessEntityID
    - JobTitle
    - HireDate

    Solution
    SELECT BusinessEntityID, JobTitle, HireDate FROM humanresources.employee WHERE HireDate > DATE '2010-01-01';

    DATE [YYYY-MM-DD] can be used to have Postgres treat the string as a date literal. This also works with other date/time types such as TIME, TIMESTAMP and INTERVAL. Doesn't generalize to other data types, so you can't write something like this INTEGER '65'

  2. Average product price by color
    Return:
    - Color
    - AveragePrice
    Sort by average price descending.

    Solution
    SELECT Color, AVG(ListPrice) AS AvgPrice FROM production.Product WHERE Color IS NOT NULL GROUP BY Color ORDER BY AvgPrice DESC;

    Checking for equality between a NULL and non-NULL value using = or <> (or its alias !=> will evaluate to a NULL, so need to be careful here. Use IS NULL or IS NOT NULL to check if a value is NULL. Here's a great article describing how NULL works in Postgres.

  3. Sales per customer
    Using Sales.SalesOrderHeader:
    Return:
    - CustomerID
    - NumberOfOrders
    Show only customers with more than 5 orders.

    Solution
    SELECT CustomerID, COUNT(*) AS NumberOfOrders FROM sales.SalesOrderHeader GROUP BY CustomerID HAVING COUNT(*) > 5;

    I initially tried SELECT CustomerID, COUNT(*) AS NumberOfOrders FROM sales.SalesOrderHeader GROUP BY CustomerID HAVING NumberOfOrders > 5;, but this produces an error Column NumberOfOrders does not exit. The HAVING clause logically comes before SELECT (physically this may not be true), so column aliases in SELECT can only be used by operations that logically come afterwards (ORDER BY). I suspect this is more of an implementation complexity problem rather than being impossible.

  4. Sales by year
    Return:
    - Year
    - NumberOfOrders
    - TotalRevenue

    Solution 
        
SELECT EXTRACT(YEAR FROM OrderDate) AS YEAR, COUNT(*) AS NumberOfOrders, SUM(TotalDue) AS TotalRevenue 
  FROM sales.SalesOrderHeader GROUP BY EXTRACT(YEAR FROM OrderDate);
    EXTRACT allows grabbing a specific field from a TIMESTAMP, DATE, TIME or INTERVAL. For example EXTRACT(MONTH FROM MyDate);

Multi-Table Queries

  1. Product names with categories
    Join:
    - Product
    - ProductSubcategory
    - ProductCategory
    Return:
    - ProductName
    - Subcategory
    - Category

    Solution 
    
SELECT Product.Name AS name, ProductSubcategory.Name AS Subcategory, ProductCategory.Name AS Category
  FROM production.Product 
  LEFT JOIN production.ProductSubcategory 
    ON Product.ProductSubcategoryID = ProductSubcategory.ProductSubcategoryID
  LEFT JOIN production.ProductCategory 
    ON ProductSubcategory.ProductCategoryID = ProductCategory.ProductCategoryID;
    Using LEFT JOINs since some products don't have a category/subcategory. Using an INNER JOIN would result in those products being omitted from the result

  2. Customer names and their sales orders
    Join:
    - SalesOrderHeader
    - Customer
    - Person
    Return:
    - CustomerID
    - CustomerName
    - SalesOrderID
    - OrderDate

    Solution 
    
SELECT Customer.CustomerID, CONCAT_WS(' ', Person.FirstName, Person.MiddleName, Person.LastName) AS name, SalesOrderHeader.SalesOrderID, SalesOrderHeader.OrderDate
  FROM sales.SalesOrderHeader
  JOIN sales.Customer 
    ON Customer.CustomerID = SalesOrderHeader.CustomerID
  JOIN person.Person
    ON Customer.PersonID = Person.BusinessEntityID
  WHERE person.PersonType = 'IN'
  ORDER BY Customer.CustomerID, SalesOrderHeader.SalesOrderID;
    CONCAT_WS will concatenate strings separated by the separator specified in the first argument. CONCAT_WS handles NULL values by replacing them with empty strings.

  3. Salespeople and their orders
    Return:
    - SalesPerson name
    - Order count

    Solution 
    
SELECT CONCAT_WS(' ', Person.FirstName, Person.MiddleName, Person.LastName) AS name, COUNT(SalesOrderHeader.SalesOrderID) AS OrderCount
  FROM person.Person
  LEFT JOIN sales.SalesOrderHeader
    ON Person.BusinessEntityID = SalesOrderHeader.SalesPersonID
  WHERE Person.PersonType = 'SP'
  GROUP BY Person.BusinessEntityID;
    Using COUNT(SalesOrderHeader.SalesOrderID) rather than COUNT(*) since that would include potential NULL values due to using LEFT JOIN. COUNT(*) includes NULL values, but COUNT([column name]) does not.
