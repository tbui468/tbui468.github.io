Learning Postgres with AdventureWorks 1

Motivation

This is a series of writeups to help me learn more about Postgres (and SQL by extension). I've recently become interested in database internals and want to test my understanding of a RDBM system before trying to get too deep into building one. The first few posts in this series will focus mainly on querying a database. I've asked an LLM to generate a series of increasingly complex tasks to use as a roadmap. The few sets are quite basic, so they will serve more as writing practice than technical.

The Database

AdventureWorks is a free database created by Microsoft that models a fictional bicycle selling business. This github repo has information/scripts to load it into Postgres: https://github.com/lorint/AdventureWorks-for-Postgres

Simple Selects

  1. List all products
    Return:
    - ProductID
    - Name
    - ListPrice
    Sort by product name.

    Solution
    SELECT ProductID, Name, ListPrice FROM production.Product ORDER BY Name;

     The tables are split into different schemas. In this case the Product table is inside the production schema. If there isn't any conflicting column names, the table name isn't necessary during projection (after SELECT).

  2. Expensive products
    Find products with a list price greater than $1000.
    Return:
    - Name
    - ListPrice
    Sort by price descending.

    Solution
    SELECT Name, ListPrice FROM production.Product WHERE ListPrice > 1000 ORDER BY ListPrice DESC;

    Nothing of note here.

  3. Employees hired after a date
    Find employees hired after January 1, 2010.
    Return:
    - BusinessEntityID
    - JobTitle
    - HireDate

    Solution
    SELECT BusinessEntityID, JobTitle, HireDate FROM humanresources.employee WHERE HireDate > DATE '2010-01-01';

    DATE can be used to have Postgres treat the following value as a date literal with the format YYYY-MM-DD.

  4. Count products
    How many products exist in the Product table?

    Solution
    SELECT COUNT(*) FROM production.Product;

    Nothing of note here.

  5. Distinct product colors
    List all unique colors used by products.
    Exclude NULL values.

    Solution
    SELECT DISTINCT Color FROM production.Product WHERE Color IS NOT NULL;

    NULL cannot be compared with a value (or another NULL) using = or !=. Use IS NULL or IS NOT NULL to check if a value is NULL.
